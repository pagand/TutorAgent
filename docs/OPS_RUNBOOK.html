Day before the exam

  1. Roster. Edit local prod/data/participants.csv (columns name,identifier,group,intervention,chat,chatiq; chat=off with chatiq=on is rejected). Run python prod/generate_tokens.py to write prod/data/manifest.csv, which holds the tokens to hand out.
    The script uses the DB your local .env points at, not prod. A token is generated only for identifiers not already in that DB, existing identifiers keep their old token. For a fresh roster use new identifiers, or delete the old participants locally first.
    Seeding never deletes. The admin delete form only wipes a student's data and resets the token to unused, so the token still logs in as a fresh student. To make a token stop working, delete its row in SQL: DELETE FROM participants WHERE token = '...'. To purge fully, delete by users.id = token, children first (skill_mastery, interaction_logs, exam_sessions, user_action_logs, chat_logs, intervention_logs, llm_usage_log), then users, then participants.
  2. Upload the roster before the box boots. Bootstrap seeds from S3, and seeding only upserts, it never deletes. To drop an old token you must delete that participant in the DB yourself. 
    ./scripts/update-prod-data.sh   # syncs prod/data to the ops bucket, re-seeds live if the box is running
  3. Schedule start and stop (EventBridge Scheduler, one-off, deletes itself after running).
    Re-read the clock first (date). A schedule set in the past fires immediately.
    D=2026-10-19   # exam date, YYYY-MM-DD
for A in start stop; do
  [ $A = start ] && T=09:00:00 && API=startInstances
  [ $A = stop ]  && T=17:00:00 && API=stopInstances
  aws scheduler create-schedule --name aitutor-$A-$D \
    --schedule-expression "at(${D}T$T)" --schedule-expression-timezone America/Los_Angeles \
    --flexible-time-window Mode=OFF --action-after-completion DELETE \
    --target "{\"Arn\":\"arn:aws:scheduler:::aws-sdk:ec2:$API\",\"RoleArn\":\"arn:aws:iam::434195712367:role/aitutor-scheduler-role\",\"Input\":\"{\\\"InstanceIds\\\":[\\\"$IID\\\"]}\",\"RetryPolicy\":{\"MaximumRetryAttempts\":5,\"MaximumEventAgeInSeconds\":3600}}"
done
aws scheduler list-schedules --query 'Schedules[].Name'
    Set the times to the real window (start about 30 minutes before students arrive).
  4. Make sure the code you want live is pushed to main (see Boot).

What happens at boot

A systemd oneshot runs scripts/ec2-bootstrap.sh on every boot. It resets the repo to origin/main, renders .env from SSM, syncs prod/data from the ops bucket, rebuilds nginx config, runs docker compose up -d --build (migrations run in the api entrypoint), waits for api healthy, then seeds participants. About 4 minutes. Code reaches prod only after it is pushed to main:

git -c credential.helper='!gh auth git-credential' push https://github.com/pagand/TutorAgent.git main

To pick up new code on a running box, reboot it or re-run the bootstrap: box "sudo systemctl restart aitutor-bootstrap".

Exam morning checks (5 minutes)

  1. Instance running: aws ec2 describe-instances --instance-ids $IID --query 'Reservations[0].Instances[0].State.Name' --output text
  2. Bootstrap finished: box "systemctl show -p ActiveState,Result aitutor-bootstrap" should show Result=success.
  3. Containers healthy: box "docker compose ps". api and db show (healthy), nginx is Up. A slow first hint after a start is normal (about 2 minutes warmup).
  4. Open https://air.da-tu.ca in a real browser, click Start the exam, and confirm the login form with the rules appears. A curl 200 is not proof the page works (a CSP once served a blank page that passed every curl check).
  5. Log in with one test token and answer one question, ask for a hint, send a chat message if the arm has chat. This proves the API key, the LLM and the DB end to end.
  6. Open the admin tunnel, Exam tab: participant count matches the roster, LLM caps look sane (150 calls per user per day, 10,000 per day).

During the exam

What to watch

  • Admin Exam tab: active sessions, LLM usage and headroom. No alert fires when a cap is near, it just starts rejecting hints and chat, so glance at it now and then.
  • Admin Health tab: in-memory request, error and latency counters, container memory. No DB queries, so it works even if the DB is struggling. Counters reset when api restarts.
  • Logs (JSON line per request, joinable by request_id): box "docker compose logs --tail 100 api". Also db and nginx. Look for 5xx and Gemini errors.
  • Tab or app switches: only absences longer than 5 seconds are recorded. The Students tab left_page column counts them per student. The detail is in Action Logs as page_leave rows, with away_ms in the action data.
  • CPU: t3 is burstable. Check the instance in the EC2 console (CPUUtilization, CPUCreditBalance). The only CPU alarm is 90% for 15 minutes, and it emails.

Incidents

Student cannot log in: token active on another device

  • Cause: one device per token. A session is released 60 seconds after the last heartbeat, so closing the old tab frees it within a minute.
  • Fix now: admin, Students, open the student, Clear Session Lock. The student retries login.

Student needs more time (or lost time to a fault)

  • One student: admin, open the student, Adjust Timer with extra minutes. Everyone: Exam tab, the bulk extend form (unsubmitted sessions only).
  • A locked-by-mistake question: student page, Unlock Question (voids that question's attempts).

Login shows "Could not reach the server"

  • Check the box first: box "docker compose ps". If it is down, see the box-unresponsive case.
  • If the box is fine, the frontend was probably built without NEXT_PUBLIC_API_KEY and every call returns 401. Check: curl -s -o /dev/null -w '%{http_code}' https://air.da-tu.ca/api/ gives 401 without a key (expected). In the browser Network tab, look at whether requests carry X-API-Key. Fix by redeploying the frontend (below).

Hints or chat failing (Gemini)

  • Check: box "docker compose logs --tail 200 api" for Google API errors, quota or key problems. Then the admin LLM usage panel: a hit cap rejects requests.
  • Fix: raise the caps on the Exam tab. For a bad key, update /aitutor/prod/google_api_key in SSM, then re-run bootstrap (it re-renders .env). The quiz itself keeps working without the LLM.

Box unresponsive, 5xx everywhere

  • Soft: box "docker compose restart api" (about 2 minutes warmup, students keep their progress, it lives in Postgres and localStorage).
  • Hard: aws ec2 reboot-instances --instance-ids $IID. Docker restarts the containers (restart: unless-stopped) and bootstrap runs again. Data in the Docker volumes survives. If SSM itself is dead, use reboot, then stop/start.
  • Timers are server-side, so a reboot costs students wall-clock time. Extend-all afterwards.

Roster change during the exam

  • Edit the csv, run python prod/generate_tokens.py (see the token caveat in Day before), then ./scripts/update-prod-data.sh. It syncs to S3 and re-seeds the live box with no reboot.
  • Changed questions need box "docker compose restart api". Do not do this mid-exam.

After the exam

  1. Export data: admin Export tab, download the logs as CSV (interactions, chat, interventions, actions). Keep a copy outside the box.
  2. Time zones: admin UI times are Vancouver time (PT, labelled PDT or PST). The export carries timestamp_utc plus timestamp_pt.
  3. Back up in an SSM session on the box (this briefly stops the api, so only after students are done): 
    aws ssm start-session --target $IID
sudo -iu ec2-user
cd AITutorApp
POSTGRES_USER=aitutor POSTGRES_DB=aitutor_db ./scripts/snapshot.sh
    Confirm it landed: aws s3 ls s3://aitutor-backups-434195712367/ --recursive | tail -3. Container logs die with the box, and the snapshot bundle captures them.
  4. Stop the instance unless the stop schedule already did: aws ec2 stop-instances --instance-ids $IID. A running t3.medium costs money all night.
  5. No leftovers: aws scheduler list-schedules --query 'Schedules[].Name' should list nothing stale (they delete themselves after firing).

Current facts

  • Exam length: 1 hour. Set by EXAM_DURATION_MS. The code default in app/utils/config.py is 60 minutes, and scripts/ec2-bootstrap.sh renders 3600000 into the box .env. Per-student and bulk extensions are done in the admin UI.
  • LLM: gemini-3.1-flash-lite, the code default in app/utils/config.py (GOOGLE_MODEL_NAME is not set in the box .env). Bootstrap sets LLM_PROVIDER=google.
  • Experiment arms per participant: group (free_choice or adaptive hint style), intervention (proactive or manual), chat (on or off), chatiq (on or off). Students cannot change them.
  • Student flow: / is a one-screen figure with a Start the exam button. It leads to /login, which shows the rules above the token form.
  • Traffic path: CloudFront serves the static frontend and proxies /api to nginx on the box. The security group admits only CloudFront ranges, so the box is not directly reachable from a laptop.
